## Setup

Layout "split": two processes on the same database: HTTP only (ROLE=http) and the workers (ROLE=worker). Logs at info to a file, AI replaying recordings, its own embedded Postgres, the fake CRM; the load generator on the same machine. Every request a new signed webhook of a fictional person.

What is measured: `POST /webhooks/:source`, from the request to the `202`. In that time the gateway checks the HMAC signature and the
rate limit, and stores the raw webhook and its job in Postgres in one transaction (the "store before answering" rule). The workers
run at the same time, on the same machine and database, processing what arrives.

Settings different from the defaults: per-caller rate limit lifted to 100000/s (one script plays every provider);
CRM calls 100/s (the fake CRM takes 200/s here).
